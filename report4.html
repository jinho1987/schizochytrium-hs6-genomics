02

Introns & UTRs for intron-mediated enhancement (IME)

A native intron sitting inside the 5′UTR (or very early in the CDS) of a highly-expressed gene is one of the more reliable, underused synthetic-biology parts — splicing deposits an Exon Junction Complex at the splice site that improves nuclear export, translation initiation, and mRNA stability. It's a well-documented effect (maize Ubi1, rice Act1 are the classic examples) that's largely independent of the promoter itself.

StringTie-assembled transcript structures (merged across all 6 RNA-seq libraries) were matched to BRAKER CDS coordinates for 9,068 of the 9,236 stable-expression candidate genes, and searched for exon-exon junctions falling entirely inside the inferred 5′UTR.

False positives caught and removed

The initial scan returned several genes with implausible 12–14 kb "5′UTRs" — almost certainly StringTie merging two adjacent genes into one assembled transcript (read-through/fusion), not real UTR structure. These were filtered out (5′UTR length capped at a generous 1.2 kb) before reporting candidates below.

04

GO/KEGG enrichment (formal statistical test)

Formal hypergeometric enrichment testing (with FDR correction) on the HS6-vs-#4 significant DE gene set — this had already been run earlier in the project but is included here for completeness since it directly strengthens the interpretation used throughout this report series.

Headline result

The actin/myosin/cytoskeleton signature among genes down in HS6 is extremely significant: GO:0051015 (actin filament binding), 30/291 genes, p.adjust = 1.7×10⁻¹³. This puts real statistical weight behind the "less cytoskeleton, faster growth" interpretation of the HS6 phenotype — not just a descriptive impression from eyeballing gene lists.

Genes up in HS6 show much weaker enrichment (best p.adjust ≈ 0.026: ferric-chelate reductase activity, high-light-intensity response) — a real but modest signal, not comparable in strength to the cytoskeleton finding.

RNA-seq-guided scaffolding

Applied the same Rascaf scaffolding approach used successfully in the sibling Chlorella HS2×ALE project (327→288 contigs, N50 +41% there) to HS6, using the existing 6 RNA-seq libraries — no new sequencing needed. Independent functional re-annotation

The project's existing GO/KEGG/COG annotation for HS6 was built by transferring strain #7's vendor-delivered annotation across the orthology map — specifically to avoid a full local eggNOG-mapper install. Running eggNOG-mapper directly against HS6's own proteome now, for an independent annotation that isn't dependent on #7's annotation quality, and to catch the ~14% of genes that failed KO conversion in the original two-hop KEGG REST API approach.

Expression-constrained flux model (crude, by design)

Built a draft genome-scale metabolic model directly from the HS6 proteome using CarveMe (homology-based reconstruction against the BiGG universal reaction database), then applied a simple E-Flux-style constraint (each reaction's flux bound scaled by its associated gene's expression level) using the normalized RNA-seq counts, separately for WT4 and HS6.

Read this before the numbers below

This is exactly the "however crude it is" version explicitly asked for. CarveMe's default draft model used a generic, BiGG-derived biomass equation not calibrated to Schizochytrium — it literally included a bacterial peptidoglycan cell-wall precursor (uaagmda_c), which a eukaryotic alga simply doesn't have, and essentially zero lipid weighting despite this being a lipid-accumulation organism (50–77% dry-weight lipid reported in the literature under lipid-accumulation conditions). That's now corrected below: peptidoglycan removed, amino-acid coefficients reduced 45%, and a fatty-acid biomass term added (palmitate-weighted, matching typical thraustochytrid storage-lipid composition — true DHA (C22:6) has no metabolite ID in this generic reconstruction database, a real limitation noted rather than hidden).

Revised interpretation — the biomass fix wasn't the actual problem

Fixing the biomass equation left the WT4:HS6 ratio essentially unchanged (~2.1× either way). That's an important, honest correction to the caveat above: the counter-intuitive "HS6 lower than WT4" ordering is not mainly a biomass-equation artifact after all — it more likely reflects a real limitation of this crude E-Flux implementation itself, which caps each reaction's flux at a value scaled by the single highest-expressed gene among its associated genes. That kind of hard, per-reaction ceiling is known to behave unevenly when two conditions have different overall expression-distribution shapes, independent of real metabolic capacity. Net effect: don't trust the absolute growth-objective comparison between strains from this method, with or without the biomass fix. The qualitative pattern — central glycolysis dominates flux capacity in both conditions, with the specific downstream branch differing (glutamate dehydrogenase vs. glycerophosphodiester metabolism) — is the only part worth treating as a weak signal.

A properly useful version of this analysis would need: (1) a real Schizochytrium biomass equation from measured composition data, not a literature-typical approximation, (2) curation of the lipid/DHA-synthesis pathway reactions, which CarveMe's generic bacterial-leaning reaction database does not represent well for a PKS-type DHA synthase system, and (3) a more sophisticated flux-constraint method than linear E-Flux (e.g. GIMME or iMAT, which handle cross-condition expression-scale differences more carefully).

Draft model files and full analysis scripts: scripts/job_fba.sh, scripts/eflux_analysis.py, scripts/eflux_lipid_biomass.py

Known tool-install gotchas hit during this work (documented so they don't cost you the same time)

  • RepeatModeler uses -pa for parallel jobs, not -threads — the wrong flag causes it to print usage and silently produce no output, which then makes RepeatMasker fail downstream with a confusing "database does not exist" error.
  • eggNOG-mapper's download_eggnog_data.py hardcodes a dead domain (eggnogdb.embl.de) in two of its three download URLs; the working domain is eggnog5.embl.de (already used correctly for the third URL in the same file). Patch with: sed -i 's|eggnogdb.embl.de|eggnog5.embl.de|g' download_eggnog_data.py.
  • bioconda's eggnog-mapper package resolves to an ancient 2.0.1 build (python2.7, no --itype flag) unless pinned; pinning an exact recent version then conflicts with biopython in the conda solver. Installing via pip install eggnog-mapper==2.1.13 into a conda env with just diamond+hmmer sidesteps both problems.
  • CarveMe's model gene IDs are SBML-sanitized (g10740_t1, underscore not dot) — strip the _t\d+ suffix before matching against a plain gene-ID expression table, or every E-Flux constraint silently evaluates to zero and the model collapses to near-zero growth for every condition identically.
